# LINE 派工技術說明

專案介紹見 [README](../README.md)。

## 資料流

```
LINE（私訊）──訊息──▶ /line/webhook ──開 issue／留言──▶ GitHub（網站 repo）
                                                          │ workflow：Claude 改 → 推 line/<issue> → 開 PR
                                                          │ → 等 Cloudflare Pages 預覽部署好 → 在 issue 回報
GitHub ──事件──▶ /github/webhook ──改好了＋預覽連結──▶ LINE（提出者）
提出者按［上線］／［取消這件］──▶ /line/webhook ──合併／關閉 PR──▶ GitHub；上線時通知管理者
```

## 行為

| 情況 | Worker 做什麼 |
| --- | --- |
| 沒審核過的人加好友，或已是好友者第一次傳訊息 | 私訊管理者「新好友：名字」＋［各網站］［忽略］按鈕；回對方「已通知管理員」。同一人只通知一次 |
| 管理者按某個網站 | 開放那個網站給對方，並傳使用說明給他 |
| 管理者按［忽略］ | 之後對方傳什麼都不理；已開放的人按忽略等於收回權限 |
| 管理者改變主意 | 以最後一次按的為準：忽略後再按網站就改成開放（並傳使用說明） |
| 開放過的人（或管理者）私訊文字 | 開帶 `line-request` 標籤的 issue，回「收到，處理中（#編號）」 |
| 同一人還有未結案的件 | 改成留言到那個 issue（追加修改），回「收到，處理中（#編號）」 |
| 被拉進群組或多人聊天室 | 自動退出（群組推播按人數計額度） |
| workflow 回報改好（它會等 Pages 預覽部署好才回報） | 推給提出者：摘要＋預覽＋［看預覽］［上線］［取消這件］ |
| workflow 反問／沒有要改的 | 推給提出者；已有預覽就不附按鈕（改好通知上的按鈕還有效），還沒有任何修改則附［取消這件］ |
| workflow 回報對方要取消（Claude 判斷對方說了「算了」「不用了」之類） | 推給提出者「要取消嗎？要繼續就直接回覆」；按鈕規則同上 |
| 提出者按［取消這件］ | 關 PR、關 issue、刪分支，回「已取消」；之後的新訊息開新件。沒按而是直接回覆的話，接著改同一件，按鈕失效 |
| workflow 失敗 | 推給提出者（按鈕規則同上）與管理者 |
| 提出者按［上線］ | squash 合併 PR、刪分支；回提出者「已上線」，私訊管理者「`<網站> <用戶> 上線`／`上線內容：<PR 變更連結>`」 |
| 舊版發出的［退回］ | 當成［取消這件］ |
| 別人按［上線］／［取消這件］ | 拒絕（管理者也不能替別人按） |
| 按到之前的［上線］／［取消這件］ | 有預覽的那組在出現更新的預覽前都有效；Claude 正在改時回「正在修改中」（讀到在改時會先查 GitHub 上有沒有回報，避免 KV 延遲誤擋）。只有［取消這件］的那組，對方回覆後就失效 |
| 在 GitHub 上直接合併／關閉／刪除 | 同步狀態；合併時通知提出者 |

**按鈕只有兩組**：新的預覽（改好通知）→［看預覽］［上線］［取消這件］；還沒有任何修改時的通知 → 只有［取消這件］。已有預覽後的其他通知不附按鈕。

GitHub 的 webhook 偶爾會漏送：一輪開始超過 5 分鐘還沒收到 workflow 的回報，每 5 分鐘一次的排程
會直接去 GitHub 讀 issue 留言，照回報補做。

## 檔案

| 路徑 | 內容 |
| --- | --- |
| `src/index.js` | 路由、LINE 與 GitHub 事件處理、排程 |
| `src/crypto.js` | LINE／GitHub 簽章驗證 |
| `src/clients.js` | LINE Messaging API、GitHub REST API 的呼叫 |
| `src/store.js` | KV 裡的成員審核狀態與件狀態 |
| `src/sites.js` | 網站設定表的讀取、預覽網址計算 |
| `src/messages.js` | 所有送到 LINE 的文字（改口吻只改這份） |
| `test/` | 自動測試（`npm test`） |
| `wrangler.toml` | Worker 設定與網站設定表（`SITES`）；憑證不在這裡，一律用 `wrangler secret` |

## 部署

以下指令都在這個資料夾裡執行（Windows 用 PowerShell 即可）。需要 Node.js 18 以上。

### 1. 安裝與登入 Cloudflare

```powershell
npm install
npx wrangler login          # 會開瀏覽器授權 Cloudflare 帳號
```

### 1-1. 建立預覽站（Cloudflare Pages）

Workers & Pages → Create → 切到 **Pages**（預設是 Worker，別走錯）→ Import an existing Git repository → 選網站的 repo：

- Project name：與 `wrangler.toml` 的 `pagesProject`、網站 workflow 的 `PAGES_PROJECT` 相同（例如 `my-site-edit-preview`）
- Production branch：`main`；Framework preset：`None`；Build command、Build output directory：**留空**

建好後專案頁顯示的網址要是 `<專案名>.pages.dev`；顯示的是 `workers.dev` 就是建成 Worker 了，刪掉重建。

### 2. 建立 KV

```powershell
npx wrangler kv namespace create STATE
```

把輸出裡的 `id` 貼到 `wrangler.toml` 的 `REPLACE_WITH_KV_NAMESPACE_ID`。

### 3. 建立 GitHub token

到 [New fine-grained token](https://github.com/settings/personal-access-tokens/new)：

- **Resource owner**：網站 repo 所屬的帳號或組織
- **Repository access**：Only select repositories → 網站的 repo
- **Repository permissions**：Contents「Read and write」、Issues「Read and write」、Pull requests「Read and write」（Metadata 會自動變成 Read-only）

組織若要求審核 fine-grained token，到組織的 Settings → Personal access tokens → Pending requests 核准。
這個 token 的擁有者就是開 issue、留言、合併 PR 的身分；它必須是 repo 協作者，workflow 才會被觸發。

### 4. 設定 secrets

逐一執行，每次會要你貼上值。第一次會問 `There doesn't seem to be a Worker called "line-dispatch"...`，回答 `y`（先建一個空的 Worker 存 secret，第 5 步部署時程式會放進去，secret 保留）：

```powershell
npx wrangler secret put LINE_CHANNEL_SECRET         # LINE Developers → channel → Basic settings
npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN   # LINE Developers → channel → Messaging API（long-lived）
npx wrangler secret put ADMIN_USER_ID               # 你自己的 userId（Basic settings 最下方 Your user ID）
npx wrangler secret put GITHUB_TOKEN                # 第 3 步的 token
npx wrangler secret put GITHUB_WEBHOOK_SECRET       # 自己產生一串亂數，第 7 步也要填同一串
```

亂數可以這樣產生：`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

### 5. 部署

```powershell
npm test                    # 先跑測試
npx wrangler deploy
```

輸出會有 Worker 網址，形如 `https://line-dispatch.<你的子網域>.workers.dev`。打開它應該看到 `line-dispatch ok`。

### 6. 接上 LINE

[LINE Developers Console](https://developers.line.biz/console/) → channel →「Messaging API」分頁：

- **Webhook URL**：`<Worker 網址>/line/webhook`
- 按 **Verify** 看到 Success，打開 **Use webhook**

### 7. 接上 GitHub

網站 repo 的 Settings → Webhooks → Add webhook：

- **Payload URL**：`<Worker 網址>/github/webhook`
- **Content type**：`application/json`
- **Secret**：第 4 步的 `GITHUB_WEBHOOK_SECRET`
- **Which events**：Let me select individual events → 勾 **Issue comments**、**Issues**、**Pull requests**（其他取消勾選）

### 8. 開放給別人用

請對方加 bot 為好友，你會在 LINE 收到「新好友：名字」和網站按鈕，按下要開放的網站就好。
對方會自動收到使用說明。不認識的人就按［忽略］。

### 9. 加新網站

1. 在 `wrangler.toml` 的 `SITES` 加一筆（`id`、`name`、`repo`、`pagesProject`），`npx wrangler deploy`。
2. 新網站的 repo：裝上 `line-request` workflow 與 `CLAUDE.md` 守則、設 `CLAUDE_CODE_OAUTH_TOKEN`、建 `line-request` 標籤、接 Cloudflare Pages。
3. 新網站的 repo 加 webhook（同第 7 步，secret 用同一組），GitHub token 也要加上這個 repo 的權限。
4. 同一個人被開放多個網站時的選擇介面還沒做，目前一律改他第一個開放的網站。

## 從舊版（白名單）升級

新版只認 `ADMIN_USER_ID`，**要先設好再部署**：

```powershell
npx wrangler secret put ADMIN_USER_ID          # 貼上你的 userId
npm test
npx wrangler deploy
```

改版前開的件與已發出的按鈕都能繼續用。原本白名單上的人要重新審核一次：他們下次傳訊息時你會收到通知。
確認新版正常後刪掉舊的 secret：

```powershell
npx wrangler secret delete APPROVER_USER_ID
npx wrangler secret delete ALLOWED_USER_IDS
```

## 開發

```powershell
npm test          # 自動測試：簽章、好友審核、上線權限、取消確認、舊資料相容、排程補送…
npm run dev       # 本機跑 Worker（需先把 .dev.vars.example 複製成 .dev.vars 並填值）
npm run tail      # 看線上 Worker 的即時紀錄
```

## 已知限制

- 每件修改的「改好了」只有 workflow 的回報這一個來源，所以不會有兩個事件同時改同一筆紀錄的問題。
- 每件大約用掉 2 則 push（給提出者的改好通知、給管理者的上線通知）；每位新好友審核用 1 則。LINE 輕用量方案每月 200 則。
- 追加修改的判定只看「同一人有沒有未結案的件」。要提另一件不相關的修改，得等前一件上線或取消。
